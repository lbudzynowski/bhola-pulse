## Source trust boundary

`debian/build-ppa-source` now requires:

1. the script to reside at the exact root of a valid Git worktree;
2. a valid committed `HEAD`;
3. a completely clean status including staged, modified, deleted, and
   untracked non-ignored files;
4. a valid configured release commit and matching release tag;
5. an unchanged installed-runtime payload relative to the release commit;
6. valid version-ordering constraints.

All checks occur before the output directory is removed or created.

The installed-runtime guard covers:

- `VERSION`;
- all of `packaging/`, including the systemd units;
- `scripts/run-dev.sh`;
- `src/`;
- `conky/`;
- `config/`.

The immutable upstream tarball is created with `git archive` from the release
commit. Top-level `debian/` is explicitly excluded. Debian packaging is added
separately with `git archive` from the committed current `HEAD`; the live
working tree is never copied. A nested `debian/debian` directory is explicitly
rejected.

Noble uses `-sa` and includes the upstream archive. Resolute uses `-sd` and
references the identical upstream archive after Noble acceptance.

## CI policy

The source-package workflow now determines whether the current installed
runtime still matches the immutable release payload.

- When it matches, the released PPA builder must succeed and its source package
  is fully extracted, rebuilt, and inspected.
- When a future pull request changes runtime code, the released builder must
  refuse it, while the separate `debian/build-pr-source` path continues to
  validate the proposed runtime through `~pr1~` packages.

This preserves the release pin without making future runtime-changing pull
requests permanently fail source-package CI.
